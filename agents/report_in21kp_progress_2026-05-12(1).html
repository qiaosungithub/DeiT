1. Executive Summary

  • Recipe alignment: Run AB ported faithfully — K=80 multi-mask, mixup_alpha=0.8 / cutmix_alpha=1.0 / switch_prob=0.5 / mixup_prob=1.0, soft_top2 view allocation, GELU MLP head (bit_dim=8, hidden=3072, 2-layer, zero-init output), AdamW b2=0.95, lr=5e-4, wd=0.02, stochastic depth=0.05, label smoothing=0.1, low augmentation. CPU smoke test verified all paths (loss ≈ log 2 = zero-init signature).
  • Best result so far: Run AB at ep12 reads 36.21% / 47.07% single-step / top-5. The curve is monotone and consistent (ep9 → 12: 34.72 → 35.00 → 35.82 → 36.21). No iterative-decode eval yet — training-time eval reports 4-step iterative; that number will land in the final eval pass.
  • Ablation point (K=10, Run N recipe): 817685 at ep17 reads 39.71% / 50.13%. Slightly ahead of Run AB on absolute number, but on fewer-parameter-update trajectory (no mixup, smaller K). Useful as a K-ablation reference.
  • Standard CE baseline: pre-crash ep28 best is 48.68% / 79.01%. Effectively converged (Δ0.02 from ep27 → 28).
  • Semantic baseline (Ridnik): severely under-trained at ep5 (5.8% top-1) due to repeated preemption on csail-shared-h200. Reported as a lower bound, not a converged baseline.
  • Cluster context: 5月 finals week on CSAIL is brutal; jobs sat in queue ~24h on shared-if-available QoS before starting. vision-pulkitag-h200 is fully booked by lab members. All four jobs are now in flight.

Net effect on expected top-1: 30 IN-21K-P epochs is roughly equivalent to 30-50 IN-1K epochs in terms of backbone gradient steps, but on a much harder discrimination task. We expect MBM Run AB to land somewhere between the collaborator's IN-1K Run AB ep59 (64.9%) and ep79 (68.5%) in difficulty-normalized terms, but absolute top-1 will be lower due to the 10× class space.

Invalid-code concern (most distinct risk)

With 36% of bit patterns invalid, MBM's iterative decoder must implicitly learn to avoid the [10450, 16383] integer range. Collaborator's final invalid_rate on IN-1K is 0.27% (118× lower than the random-baseline 2.3%). If the same suppression ratio holds, our 14-bit invalid_rate at convergence should land near 36% × (0.27 / 2.3) ≈ 4%. If the suppression instead scales as absolute residual (0.27% directly), our invalid_rate could be ≤1%. The training-time check at ep12 will clarify; we will report invalid_rate per inference configuration in the final eval.

6. Caveats

  • Recipe asymmetry between MBM and CE/semantic baselines. Standard CE (817683) and Semantic (817684) were trained with the legacy recipe (max_lr=3e-4, wd=1e-4, label_smoothing=0.2, RandAugment, RandomErasing, grad_clip=1.0) — designed for those heads. MBM Run AB uses the masked-bit recipe. We do not retrain the baselines under the new recipe; compute constraints make a third round infeasible. The asymmetry is two-directional: MBM's low-aug recipe is unfair to MBM if compared head-to-head with high-aug CE; CE's recipe is unfair to itself if forced into MBM's low-aug regime.
  • Semantic is severely under-trained. Repeated preemption on csail-shared-h200 prevented completion of full epoch + val cycles. model_best.pth on disk is from epoch 5 (top-1 = 5.8%). Ridnik et al. report ~37% top-1 at convergence on the same architecture. We report 5.8% as a lower bound, not a converged baseline.
  • Standard crashed at ep28 from an OneCycleLR over-step. An IterableDataset jitter pushed the actual step count one past the precomputed total_steps, raising ValueError. Fixed retroactively with a try/except ValueError around scheduler.step(). Pre-crash ep28 best (48.68% / 79.01%) is preserved and is the basis for the reported standard baseline; resume continues from model_last.pth.
  • 30 epochs is a constrained budget. Collaborator's Run AB needed 99 epochs to hit 70% top-1 on IN-1K. We can only afford 30 epochs here. Reported numbers should be interpreted as "30-epoch budget result", not "converged result".
  • Wandb step-collision bug discovered. Per-epoch val/* wandb logs were silently dropped due to step collision with per-step train logs (IterableDataset jitter pushes the per-step counter past the precomputed (epoch+1) × steps_per_epoch). Fixed via wandb.define_metric("val/*", step_metric="epoch") + dropping the explicit step argument on per-epoch logs. Historical SLURM stdout contains all per-epoch numbers; retroactive backfill to wandb is straightforward.
  • Hierarchy encoding ablation not run. The codebase supports --encoding=hierarchy (re-permute class indices so high-order bits track WordNet ancestor levels). Compute budget did not allow a second MBM variant. Hierarchy encoding remains the most-promising future-work direction: it directly addresses both the remasking negative result and the top-K diversity issue.

7. Open Questions for Collaborator

  • CutMix small-patch tail case. With K=80 and a CutMix lam ≈ 0.99 (small patch), soft_top2 round-to-integer view allocation gives 79/1 split: the secondary class gets only one mask view, which is a noisy supervision signal. Did you observe degradation in trajectory health for cutmix-dominated batches, or is this tail behavior absorbed into the K=80 average?
  • Invalid-code rate scaling. Your IN-1K final invalid_rate is 0.27% with 2.3% of bit patterns invalid. Did you observe how invalid_rate scales with the fraction of invalid bit patterns? We have 36% invalid space on 14 bits — ~16× yours. We expect somewhere between 0.3% (if the model learns the same absolute residual) and 4% (if it learns the same suppression ratio), but the actual trajectory matters for whether hierarchy encoding becomes more urgent.
